# Branch readiness checklist — portfolio template

> **Illustrative reconstruction.** This is a generalized checklist derived from the contributor's description of POS rollout responsibilities. It is not the employer's original checklist, does not contain branch data, and should not be treated as proof every item was checked identically at every branch.

| Area | Example readiness question | Result |
|---|---|---|
| Rollout coordination | Has the branch been informed of the assigned deployment window and implementation activities? | Pass / Action needed / N/A |
| Endpoint hardware | Are the POS workstation and needed peripherals available and functional? | Pass / Action needed / N/A |
| Connectivity | Can the workstation reach the required internal application/network services? | Pass / Action needed / N/A |
| Application environment | Are the necessary POS components available and able to start? | Pass / Action needed / N/A |
| Access | Do designated users have the access needed for testing and operation? | Pass / Action needed / N/A |
| Workflow validation | Are the relevant POS transaction scenarios ready for UAT? | Pass / Action needed / N/A |
| Training | Are branch users available for orientation on the new application? | Pass / Action needed / N/A |
| Go-live | Are critical defects resolved or escalated to the appropriate decision-maker? | Pass / Action needed / N/A |
| Support transition | Does the branch know how to report a post-live issue? | Pass / Action needed / N/A |

## Coordination approach

The central distinction is between **owning the master schedule** and **coordinating execution**. The schedule was assigned to the contributor. Their implementation responsibility involved preparing each branch for its scheduled work, communicating with relevant people, undertaking deployment and testing, and following up on blockers.

No live IP addresses, store identifiers, configuration files, account names or other internal environment details are included.
